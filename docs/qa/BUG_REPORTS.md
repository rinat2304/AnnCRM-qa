# AnnCRM — Bug Reports

## BUG-001 — Создание дубликатов клиентов

| Поле | Значение |
|---|---|
| ID | BUG-001 |
| Title | Возможно создание дубликатов клиентов |
| Severity | Major |
| Priority | High |
| Status | Open |
| Component | Clients |
| Layer | Backend / API + Frontend / UI |
| Environment | Test Environment |
| Found during | Baseline testing |

---

## Description

Система позволяет создать несколько клиентов с полностью идентичными данными.

Согласно бизнес-правилу, один пользователь не должен иметь возможность создать дубликат уже существующего клиента.

---

## Preconditions

1. Пользователь авторизован.
2. В системе существует клиент с определённым набором данных.

---

## Steps to Reproduce — API

1. Авторизоваться в системе.
2. Создать клиента с валидными данными.
3. Повторно отправить запрос на создание клиента.
4. Передать полностью идентичные данные.

---

## Steps to Reproduce — UI

1. Авторизоваться в системе.
2. Открыть раздел Clients.
3. Создать клиента.
4. Повторно открыть форму создания клиента.
5. Ввести те же данные.
6. Сохранить клиента.

---

## Expected Result

Система должна отклонить создание дубликата.

Пользователь должен получить понятное сообщение о том, что клиент с такими данными уже существует.

---

## Actual Result

Система позволяет создать второго клиента с полностью идентичными данными.

При этом созданные записи получают разные `id`.

---

## Reproducibility

**100%**

---

## Business Impact

Наличие дубликатов может привести к:

- некорректным данным в CRM;
- дублированию клиентской информации;
- ошибкам в статистике;
- проблемам при дальнейшем редактировании и удалении клиентов;
- потенциальным ошибкам бизнес-логики, использующей данные клиента.

---

## Suggested Fix

Добавить проверку уникальности клиента на стороне backend.

Проверка должна выполняться независимо от frontend, чтобы правило нельзя было обойти прямым API-запросом.

Желательно обеспечить защиту на уровне базы данных, если бизнес-правило позволяет однозначно определить уникальность записи.

## Retest

После исправления необходимо проверить:

1. Создание первого клиента.
2. Повторное создание клиента с полностью идентичными данными через API.
3. Повторное создание клиента с полностью идентичными данными через UI.
4. Создание клиента с частично совпадающими данными.
5. Одновременные запросы на создание одинакового клиента.
6. Невозможность обхода ограничения через прямой API-запрос.
