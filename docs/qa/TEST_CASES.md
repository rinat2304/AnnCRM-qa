# 1. Формат тест-кейса

Каждый тест-кейс содержит:

- ID;
- название;
- тип;
- приоритет;
- предусловия;
- тестовые данные;
- шаги;
- ожидаемый результат.

Результаты выполнения тестов хранятся отдельно в `TEST_EXECUTION_REPORT.md`.

# 2. Регистрация

## AUTH-REG-001 — Успешная регистрация

**Тип:** Функциональный  
**Приоритет:** High

### Предусловия

Пользователь с указанными данными отсутствует в системе.

### Тестовые данные

Уникальные имя, email и валидный пароль.

### Шаги

1. Открыть страницу регистрации.
2. Ввести валидное имя.
3. Ввести уникальный email.
4. Ввести валидный пароль.
5. Нажать кнопку регистрации.

### Ожидаемый результат

Пользователь успешно зарегистрирован.

---

## AUTH-REG-003 — Регистрация с уже существующим email

**Тип:** Негативный  
**Приоритет:** High

# 8. Клиенты — Бизнес-правила

## CLIENT-014 — Создание дубликата клиента через API

**Тип:** Негативный / Бизнес-правило  
**Приоритет:** High

### Связанное требование

**BR-CLIENT-001**

Пользователь не может создать клиента с полностью идентичным набором данных уже существующего клиента.

### Предусловия

В системе уже существует клиент с определённым набором данных.

### Шаги

1. Авторизоваться.
2. Создать клиента с валидными данными.
3. Повторно отправить запрос на создание клиента с полностью идентичными данными.

### Ожидаемый результат

Система отклоняет создание дубликата.
