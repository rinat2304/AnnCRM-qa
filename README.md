# AnnCRM — QA Automation Project

QA-проект по комплексному тестированию CRM-системы **AnnCRM**.

Проект демонстрирует полный цикл QA: от разработки тестовой документации и проведения ручного тестирования до автоматизации API-тестов, формирования Allure-отчётов и запуска автоматизированных тестов в CI/CD.

## 🎯 О проекте

В рамках проекта выполнено тестирование следующих функциональных областей:

* аутентификация;
* регистрация пользователей;
* авторизация пользователей;
* управление клиентами;
* CRUD-операции;
* контроль доступа;
* изоляция данных пользователей;
* негативные сценарии;
* проверка API.

Автоматизированные тесты взаимодействуют с backend API реального проекта **AnnCRM**.

## ⚙️ Тестовое окружение

Для автоматизированного тестирования используется отдельная тестовая база данных **PostgreSQL**.

CI/CD-пайплайн автоматически выполняет следующие действия:

1. запускает PostgreSQL;
2. устанавливает Python;
3. устанавливает зависимости QA-проекта;
4. загружает backend;
5. устанавливает зависимости backend;
6. применяет миграции базы данных;
7. запускает backend;
8. проверяет доступность API;
9. создаёт тестовых пользователей;
10. запускает API-тесты;
11. формирует результаты для Allure.

## ▶️ Запуск тестов локально

### 1. Клонирование репозитория

```bash
git clone https://github.com/rinat2304/AnnCRM-qa.git
cd AnnCRM-qa
```

### 2. Создание виртуального окружения

Для Windows:

```powershell
python -m venv .venv
```

### 3. Активация виртуального окружения

```powershell
.venv\Scripts\Activate.ps1
```

### 4. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 5. Запуск API-тестов

```bash
pytest tests/api -v
```

## 📊 Allure-отчёт

Для формирования результатов тестирования в формате Allure необходимо выполнить:

```bash
pytest tests/api -v --alluredir=allure-results
```

После установки Allure Report отчёт можно запустить командой:

```bash
allure serve allure-results
```

Allure позволяет просматривать:

* общее количество тестов;
* количество пройденных и непройденных тестов;
* статусы `passed / failed / broken / skipped`;
* длительность выполнения тестов;
* наборы тестов;
* stack traces;
* историю выполнения тестов.

## 🔄 CI/CD

Для автоматического запуска тестов используется **GitHub Actions**.

Workflow находится в:

```text
.github/workflows/tests.yml
```

Тесты запускаются автоматически при:

* `push`;
* `pull request`.

### Этапы CI/CD-пайплайна

```text
Клонирование QA-репозитория
        ↓
Установка Python
        ↓
Установка QA-зависимостей
        ↓
Загрузка backend
        ↓
Установка backend-зависимостей
        ↓
Запуск PostgreSQL
        ↓
Применение миграций
        ↓
Запуск backend
        ↓
Проверка доступности API
        ↓
Создание тестовых пользователей
        ↓
Запуск pytest
        ↓
Формирование результатов Allure
```

## 📌 Цели проекта

Основная цель проекта — продемонстрировать практический подход к **QA Automation** и полный цикл тестирования программного продукта:

```text
Требования
     ↓
Тест-кейсы
     ↓
Ручное тестирование
     ↓
API-автоматизация
     ↓
Подготовка тестовых данных
     ↓
CI/CD-пайплайн
     ↓
Allure-отчёт
     ↓
Результаты тестирования
```

Проект показывает, как ручное тестирование и автоматизация могут быть объединены в единый процесс контроля качества.
